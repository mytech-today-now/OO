Failure mode

The current implementation creates a per-run profile snapshot under the managed O&O directory, verifies the directory and both files with Test-SystemTaskTargetAcl, writes the files exclusively, rechecks the approved digests, and retains the snapshot until O&O exits. The offline harness uses mocked ACL records. A test double cannot establish the effective NTFS access rules on a supported Windows host, so a release may rely on the ACL boundary without evidence that the intended lower-privilege account cannot alter or remove the snapshot.

Evidence or rationale

Install-OOShutUp10.ps1 defines New-OOShutUpProfileSnapshot and Remove-OOShutUpProfileSnapshot and calls the snapshot path before launching O&O. The profile trust harness contains ACL fixtures and digest assertions. README states that the offline harness uses mocked ACL records and explicitly requires a disposable VM run with two test accounts to inspect the snapshot while a harmless reviewed fixture is used. No such VM result is checked into the repository or available in this review.

Testable assumption: The ACL inspection and file creation behavior may differ across supported Windows versions, filesystem inheritance states, and account tokens. A two-account VM acceptance run could confirm or disprove whether the actual effective permissions match the intended SYSTEM and Administrators allowlist.

Why this matters

The snapshot is the exact cfg and manifest pair consumed by O&O. If a less-privileged account can create, modify, replace, or delete either file during the privileged operation, the operator-approved digest no longer necessarily describes the bytes O&O reads. The source has fail-closed checks, but release confidence for a Windows security boundary still needs host-level evidence.

Recommended mitigation

Keep the existing exclusive creation, ACL checks, and digest verification. Make the documented two-account VM run a release acceptance gate and record the OS build, directory and file owner/DACL, tested account identities, attempted create/modify/replace/delete operations, and cleanup result. Use a harmless fixture profile in the disposable VM. If any access check differs from the documented allowlist, stop before O&O starts, preserve the snapshot for diagnosis, and fix the ACL or path before retrying. Do not weaken ACL checks to make the fixture pass.
